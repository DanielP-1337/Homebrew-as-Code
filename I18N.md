# HBAC localization

HBAC 0.4.0-beta.2 includes English (`en-US`, fallback), German (`de`), French (`fr`),
Spanish (`es`), Italian (`it`), Portuguese (`pt`), Polish (`pl`) and Dutch (`nl`).
This is the agreed initial language set, not a statistical ranking of languages.

The operating card, inline instructions, separate help card, statuses, conversion
notes, HBAC errors and native HA setup/action labels are localized. Source recipe
names, ingredient names and diagnostic messages from external integrations retain
their original text. The initial translations have automated key/placeholder checks;
native-speaker wording improvements are welcome.

## Select a language

Cards use the HA user's `hass.locale.language`, with `hass.language` as compatibility
fallback. They update when the profile language changes. To override one card:

```yaml
type: custom:hbac-card
language: nl
```

The instructions are available inside the operating card and as their own card:

```yaml
type: custom:hbac-help-card
```

Both are registered by `/hbac/hbac-card.js?v=0.4.0-beta.2`. The help card does not
call services or poll the device. See [the complete dashboard](dashboard/hbac-test.yaml).
Dashboard tab titles are intentionally language-neutral; dashboard YAML itself does
not resolve HBAC translations. Replace the old German Markdown help view with the
help card to make its instructions follow the user's language.

## Add a language locally, without changing JavaScript

1. Copy [en-US.json](custom_components/hbac/frontend/locales/en-US.json).
2. Translate the **values**, keeping all keys and `{placeholders}` intact.
3. Save as UTF-8 JSON at `/config/www/hbac/locales/sv.json`, for example.
4. Reload the browser. Use HA's Swedish profile language or `language: sv` on the card.

You can start with a partial file:

```json
{
  "ui.help": "Instruktioner och testflöde",
  "ui.upload": "Ersätt alla platser"
}
```

Every missing key uses the matching bundled language or `en-US`. Files in `www`
are user-owned and are not overwritten by an integration update. If `www` did not
exist when HA started, HA may require a restart before serving `/local/` files.
Subsequent JSON edits only require a browser reload. The files are public static
resources: do not put credentials or other private data in them.

Use canonical language tags: `sv`, `de-CH`, `pt-BR`, etc. Lookup, in priority order:

1. User file for the exact locale (`/local/hbac/locales/de-CH.json`).
2. Bundled file for that exact locale.
3. User file for its base language (`de.json`).
4. Bundled base language.
5. `en-US`, with an optional user `en-US.json` override.
6. Embedded complete `en-US` fallback, even when all JSON requests fail.

Malformed JSON, non-string/empty values and mismatched placeholders are ignored;
the fallback remains available. Language tags are validated before creating paths.
All translations are rendered as text, never HTML. Reload the browser to clear the
per-page translation cache after adding or changing a file.

## Contribute a language to the repository

Add `custom_components/hbac/frontend/locales/<language>.json`. This is sufficient
for the operating/help cards: no language registry or JavaScript code change is needed.
For native HA configuration dialogs, service labels, sensor labels and exceptions,
also generate the HA-format file:

```text
python scripts/build_ha_metadata.py
node tests_frontend/i18n.test.cjs
```

HA uses `translations/en.json`; its contents are generated from the `en-US` catalog.
HA's own supported profile languages govern its native dialogs. A card-only language
can always be selected with the card's `language` setting.

When changing the English fallback, `message_sources.json` or localization
engine, also run `python scripts/build_frontend_i18n.py`. It refreshes the embedded
fallback in `hbac-card.js`. Existing Beta 1 queue data is not rewritten: legacy
German messages are recognized by the immutable source templates in
`message_sources.json` and localized for display. Translators edit locale JSON,
not that compatibility file; improving German wording therefore cannot break
recognition of existing queue messages.
Recipe programs, queue ordering, upload consent and job IDs do not change when the
display language changes. There is no automatic device upload during localization.
